# Pi_test V2 — วิธีใช้

สคริปต์ทดสอบการคุยกับ MCU (Arduino Mega) โดย **ไม่ต้องมี Backend และ MySQL**

---

## ต้องเตรียมอะไรก่อน

| | |
|---|---|
| **Mega เสียบ USB** | บังคับ — สคริปต์หาพอร์ตเองจาก `/dev/ttyACM*` หรือ `/dev/ttyUSB*` ถ้าไม่เจอจะปิดตัวเองทันที |
| **ESP ฟัง TCP** | ที่ `TMX_HOST:TMX_PORT` ใน `.env` (ตอนนี้ `192.168.10.11:8600`) ทำหน้าที่แทน TM-X ตอบ `R0` / `PW` / `MRS` / `T1` / `GM` ตาม `ESP_PROTOCOL.md` |
| Backend / MySQL | **ไม่ต้องมี** |

```bash
pip install -r requirements.txt
python "Pi_test V2.py"
```

ขึ้นแบบนี้แปลว่าพร้อม

```
[INFO] Connecting to Mega on /dev/ttyACM0 @ 115200 baud ...
[INFO] Mega Serial Connected Successfully.
```

## 1. แก้ scenario ใน `Pi_test_payload.json`

ไฟล์อยู่ข้างๆ สคริปต์ หน้าตาเหมือน payload จริงที่ Backend ยิงมาทุกประการ

```json
{
  "target_count": 4,
  "groups": [
    { "template_name": "1", "alpl": [201, 202], "package_size": "8x8",
      "limits": { "x_lo": 8.02, "x_hi": 8.05, "y_lo": 8.02, "y_hi": 8.05, "offset_max": null } },
    { "template_name": "1", "alpl": [203, 204], "package_size": "3.255x3.255",
      "limits": { "x_lo": 3.275, "x_hi": 3.305, "y_lo": 3.275, "y_hi": 3.305, "offset_max": null } }
  ]
}
```

**กฎเดียวที่ห้ามผิด** — จำนวน ALPL รวมทุกกลุ่มต้องเท่ากับ `target_count` เป๊ะ
(ตัวอย่างนี้ `[201,202] + [203,204]` = 4 ตัว = `target_count: 4`)

ถ้าไม่ตรง สคริปต์จะปฏิเสธพร้อมบอกตัวเลขทั้งสองฝั่ง ไม่ปล่อยให้เริ่มวัด

### อยากเทสต์อะไร แก้ตรงไหน

| อยากได้ | แก้ |
|---|---|
| วัดกลุ่มเดียว | เหลือ `groups` แค่ก้อนเดียว แล้วลด `target_count` ให้ตรง |
| วัดเยอะขึ้น | เพิ่มเลขใน `alpl` แล้วเพิ่ม `target_count` ให้ตรง |
| เปลี่ยนขนาดชิ้นงาน | แก้ `package_size` และ `limits` ให้ตรงกัน (ดูค่าที่ใช้ได้ใน `_comment` ท้ายไฟล์) |
| ให้ตรวจ offset ด้วย | เปลี่ยน `"offset_max": null` เป็น `"offset_max": 0.03` |
| ให้ชิ้นงานเป็น NG | ตั้ง `limits` ให้แคบจนค่าที่ ESP ตอบมาหลุดขอบ |

**แก้แล้วไม่ต้องรีสตาร์ท** — กดเริ่มรอบใหม่มันอ่านไฟล์ใหม่ให้เอง

## 2. พิมพ์ในเบราว์เซอร์

```
http://127.0.0.1:9998/
```

**แค่นี้** — เริ่มวัดตาม scenario ในไฟล์ทันที

จะตอบกลับมาแบบนี้ ให้เช็คว่า `groups` ตรงกับที่ตั้งใจไหม

```json
{
  "ok": true,
  "session_id": 1,
  "target_count": 4,
  "from_file": "Pi_test_payload.json",
  "groups": [
    {"package_size": "8x8", "template_name": "1", "alpl": [201, 202]},
    {"package_size": "3.255x3.255", "template_name": "1", "alpl": [203, 204]}
  ],
  "next": "รอสัญญาณ <TRIGGER_TMX> จาก Mega ผ่าน Serial"
}
```

### URL อื่นที่ใช้ระหว่างเทสต์

| URL | ทำอะไร |
|---|---|
| `http://127.0.0.1:9998/` | **เริ่มวัด** (อ่านจากไฟล์ json) |
| `http://127.0.0.1:9998/stop` | หยุดกลางคัน |
| `http://127.0.0.1:9998/status` | ดูว่าตอนนี้เดินถึงชิ้นไหนแล้ว |
| `http://127.0.0.1:9998/mock/db` | ดูค่าที่ "ลง DB" ไปแล้วทั้งหมด |
| `http://127.0.0.1:9998/answer/retry` | ตอบตอนระบบเด้งถาม — วัดชิ้นเดิมใหม่ |
| `http://127.0.0.1:9998/answer/accept` | ตอบ — รับค่าที่อ่านได้ไปเลย |
| `http://127.0.0.1:9998/answer/stop` | ตอบ — หยุดทั้งรอบ |

เปิดในเบราว์เซอร์ได้ทุกอัน ไม่ต้องใช้ `curl`

### เริ่มแบบเร็ว ไม่แตะไฟล์

```
http://127.0.0.1:9998/start?count=3&package_size=8x8
http://127.0.0.1:9998/start?count=4&package_size=8x8&package_size_2=3.255x3.255
```

## ลำดับข้อความที่จะเห็นบนสาย Serial

```
Pi → Mega   <PKG:8x8>              ส่งตอนขึ้นกลุ่มใหม่เท่านั้น ไม่ได้ส่งทุกชิ้น
Pi ← Mega   <TRIGGER_TMX>          Mega บอกว่าชิ้นงานเข้าที่แล้ว
Pi → Mega   <MEASURE_OK>           ผลวัดชิ้นนั้น
Pi ← Mega   <TRIGGER_TMX>          ชิ้นถัดไป
Pi → Mega   <MEASURE_NG>
Pi → Mega   <PKG:3.255x3.255>      เปลี่ยนกลุ่ม ขนาดเปลี่ยน
Pi ← Mega   <TRIGGER_TMX>
Pi → Mega   <MEASURE_OK>
```

**ฝั่ง Mega ต้องจำ `<PKG:...>` ไว้เอง** เพราะมันมาเฉพาะตอนเปลี่ยนกลุ่ม
ชิ้นที่ 2 ในกลุ่มเดียวกันจะไม่ได้รับซ้ำ

ทุกข้อความปิดท้ายด้วย `\n` · ยาวสุดคือ `<PKG:3.255x3.255>\n` = **18 ไบต์** buffer ต้องเผื่ออย่างน้อยเท่านี้

## ⚠ สิ่งที่ยังไม่ได้ทำในเวอร์ชันนี้ (ตั้งใจข้าม)

ถ้าเจออาการพวกนี้ **ไม่ใช่บั๊กฝั่ง Mega** ไม่ต้องไปไล่หา

| อาการ | สาเหตุ |
|---|---|
| TM-X วัดไม่ติด แล้ว Mega ไม่ได้รับอะไรเลย | `UNKNOWN` ยังไม่ถูกส่งให้ MCU — Pi จบ session เงียบๆ |
| สาย USB หลุดแล้ว session ตายโดยไม่บอกสาเหตุ | `send_result_to_mcu()` ยังไม่มี try/except คืน `True` เสมอ |
| นานๆ ครั้งวัดก่อนที่จะวางชิ้นงาน | ยังไม่ล้าง buffer ก่อนรอสัญญาณ สัญญาณค้างจากรอบก่อนถูกหยิบมาใช้ |

## ค่าที่ปรับได้จาก `.env`

| ตัวแปร | ค่าตอนนี้ | ผล |
|---|---|---|
| `AGENT_PORT` | 9998 | พอร์ตของหน้าเว็บนี้ |
| `TMX_HOST` / `TMX_PORT` | 192.168.10.11 : 8600 | ที่อยู่ของ ESP ที่แทน TM-X |
| `MEASURE_TIMEOUT` | 15 | รอค่าเข้า DB จำลองกี่วินาทีก่อนเด้งถาม |
| `ASK_USER_TIMEOUT` | 62 | ไม่มีใครตอบใน `/answer/...` กี่วินาทีถึงถือว่าหยุด |
| `MOCK_MEASURE_DELAY` | 1.0 | หน่วงกี่วินาทีก่อนถือว่า "ค่าเข้า DB แล้ว" |

**ตั้ง `MOCK_MEASURE_DELAY` ให้มากกว่า `MEASURE_TIMEOUT`** เมื่อไหร่ จะได้ทดสอบเส้นทาง "วัดได้แต่ค่าไม่ถึง DB" ที่เด้งถาม retry / accept / stop
