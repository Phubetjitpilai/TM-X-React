# สเปคที่ ESP ต้องตอบ เพื่อแทน TM-X ตอนเทสต์กับ `Pi_test.py`

ESP ทำตัวเป็น **TCP server** รอ `Pi_test.py` ต่อเข้ามา — ตั้ง IP/พอร์ตให้ตรงกับ
`TMX_HOST` / `TMX_PORT` ใน `.env` (ของจริงคือ `192.168.10.11:8600`)

## กติกาพื้นฐาน — ผิดข้อไหนข้อหนึ่งคือใช้ไม่ได้เลย

| ข้อ | รายละเอียด |
|---|---|
| **ตัวคั่น** | ทุกข้อความ **ปิดท้ายด้วย `\r` (CR, 0x0D)** ตัวเดียว — ไม่ใช่ `\n` และไม่ใช่ `\r\n` |
| **การเข้ารหัส** | ASCII ล้วน |
| **1 คำสั่ง = 1 คำตอบ** | ห้ามตอบ 2 ข้อความติดกันต่อ 1 คำสั่ง |
| **ต่อได้ทีละสายเดียว** | Pi เปิด TCP ค้างไว้ตลอด session แล้วส่งทุกคำสั่งผ่านสายเดิม |

⚠ **เรื่อง `\r` สำคัญที่สุด** — `send_recv()` (`Pi_test.py:306`) วน `recv` จนกว่าจะ
เจอ `\r` ถ้า ESP ไม่ส่งมา Pi จะรอจนครบ `SOCKET_TIMEOUT` (5 วิ) ทุกคำสั่ง แล้วคืน
`<timeout>` — อาการคือ "ช้ามากและพังทุกขั้น" ซึ่งดูเหมือนปัญหาเครือข่าย

---

## สรุป: คำสั่งไหนบังคับให้ตอบบ้าง

ทดสอบจริงแล้วทุกช่อง โดยให้ ESP จำลอง "เงียบใส่" ทีละคำสั่ง

| คำสั่ง | ต้องตอบไหม | ตรวจเนื้อหาที่ตอบไหม | ไม่ตอบแล้วเกิดอะไร |
|---|---|---|---|
| `R0` | **บังคับ** | ❌ ไม่ตรวจเลย | `TimeoutError` ใน 5 วิ → **session ตายทันที** ยังไม่ทันเริ่มวัด |
| `PW,1,nnn` | **บังคับ** | ❌ ไม่ตรวจเลย | เหมือน `R0` — ตายที่ขั้นนี้ |
| `MRS`/`MSR` | ⚠ ไม่บังคับ | ✅ ตรวจ (`ER` = ไม่ผ่าน) | เสียเวลา 10 วิ (ลอง MRS 5 + MSR 5) → เตือน → **วัดต่อได้** แต่เสี่ยงหนัก (ดูด้านล่าง) |
| `T1` | **บังคับ** | ✅ ตรวจ | `<timeout>` ใน 5 วิ → ถือว่ายิงไม่สำเร็จ → เด้งถามผู้ใช้ / หยุด session |
| `GM,3,0` | **บังคับ** + ต้องมีค่าจริง | ✅ ตรวจ + พาร์ส | วน 8 วิ → `TM-X วัดชิ้นนี้ไม่ติด` → ผล `UNKNOWN` |
| `S0` | ไม่บังคับ | ❌ | ไม่มีผล (โค้ดปัจจุบันไม่ได้ส่ง `S0` ด้วยซ้ำ) |

**อ่านตารางนี้ยังไง**

- `R0` กับ `PW` — Pi **ไม่สนใจว่าตอบว่าอะไร** เอาไปพิมพ์ log เฉยๆ ตอบ `ER,PW,02`
  หรือตอบมั่วก็เดินต่อ · **แต่ต้องมีอะไรตอบกลับมา** ไม่งั้นค้างจนหมด 5 วิแล้วตาย
  (ใช้ `send_command()` ที่ `recv` ครั้งเดียว ไม่วนหา `\r` — ที่จริงไม่ใส่ `\r`
  ก็รอด แต่ใส่เถอะ จะได้ไม่ต้องจำว่าคำสั่งไหนต้องใส่ไม่ต้องใส่)
- `MRS`/`T1`/`GM` — ตรวจจริง ขึ้นต้นด้วย `ER` = ไม่ผ่าน และ **ต้องปิดท้ายด้วย `\r`**

⚠ **`MRS` ไม่บังคับก็จริง แต่ห้ามข้าม** — `GM` ดึง "ค่าของภาพล่าสุด" โดยไม่มีเลข
ลำดับกำกับ ถ้าไม่ล้างค่าเก่าแล้วรอบนี้วัดไม่ติด `GM` จะคืน **ค่าของชิ้นก่อนหน้า**
มาให้เงียบๆ แล้วระบบจะตัดสินชิ้นใหม่ด้วยตัวเลขของชิ้นเก่า **แล้วสั่ง MCU ขยับของ
จริงตามนั้น** · ให้ ESP รองรับสักตัว (จะ `MRS` หรือ `MSR` ก็ได้) แล้วตัวที่เหลือ
ตอบ `ER,MRS,02` ก็พอ — Pi จะจำตัวที่ใช้ได้ไว้ ไม่ลองซ้ำอีกทั้ง session

## คำสั่งที่ Pi ส่งไป เรียงตามลำดับจริง

### 1. `R0` — เข้าโหมดดำเนินงาน (ครั้งเดียวตอนเริ่ม session)

```
Pi  → R0\r
ESP → R0\r
```

### 2. `PW,1,nnn` — โหลดโปรแกรมวัด (ครั้งเดียวตอนเริ่ม session)

```
Pi  → PW,1,201\r
ESP → PW\r
```

`nnn` คือ `template_name` เติมศูนย์หน้าให้ครบ 3 หลัก

### 3. `MRS` หรือ `MSR` — ล้างค่าเก่า (**ทุกชิ้น ก่อน `T1` เสมอ**)

```
Pi  → MRS\r
ESP → MRS\r          ← ถ้ารองรับ
```

หรือถ้าอยากให้ ESP รองรับแค่ตัวเดียว ให้อีกตัวตอบ error

```
Pi  → MRS\r
ESP → ER,MRS,02\r    ← Pi จะเปลี่ยนไปลอง MSR แล้วจำไว้ใช้ตลอด session
Pi  → MSR\r
ESP → MSR\r
```

⚠ **รองรับอย่างน้อย 1 ตัว** — ถ้า error ทั้งคู่ Pi จะเตือนแล้ววัดต่อ ซึ่ง `GM`
อาจคืนค่าของชิ้นก่อนหน้ามาให้ (`clear_measurement()` — `Pi_test.py:381`)

### 4. `T1` — สั่งวัด 1 ชิ้น

```
Pi  → T1\r
ESP → T1\r
```

**ตอบทันทีตอนรับคำสั่ง ไม่ต้องรอวัดเสร็จ** — ของจริงใช้เวลาวัดราว 24 ms หลังตอบ

ถ้าอยากให้ ESP บอกว่า "ยังไม่พร้อม" (Pi จะลองใหม่ `T1_RETRY` = 3 ครั้ง)

```
ESP → ER,T1,03\r
```

⚠ **ต้องเป็นรหัส `03` เท่านั้นถึงจะลองใหม่** — รหัสอื่นทั้งหมด Pi ถือว่าล้มเหลว
ทันทีแล้วจบ session (ดู `trigger_tmx()` — `Pi_test.py:412`)

### 5. `GM,3,0` — ดึงค่าที่วัดได้ (**Pi วนถามทุก 20 ms จนกว่าจะได้ค่าจริง**)

**นี่คือคำสั่งที่ยากที่สุด ต้องทำให้ถูก**

```
Pi  → GM,3,0\r
ESP → GM,8,<m>,<i>,<j>,<m>,<i>,<j>, ... รวม 8 ชุด ...\r
```

รูปแบบ `GM,<จำนวนเครื่องมือ>,` แล้วตามด้วย **3 ค่าต่อเครื่องมือ**

| | ความหมาย |
|---|---|
| `m` | ค่าที่วัดได้ |
| `i` | สถานะ — `0` ไม่ทำงาน · `1` ปกติ · `2` แก้ตำแหน่งล้มเหลว · `3` ข้อมูลไม่ถูกต้อง · `4` รอตัดสิน |
| `j` | ผลตัดสินของเครื่องเอง — `0` OK · `1` NG |

**ลำดับของ 8 เครื่องมือ** (ต้องเรียงตามนี้ — ตรงกับ `GM_IDX_*` ใน `.env`)

| ช่อง | คือ | ตัวอย่าง |
|---|---|---|
| 0 | ขนาดแกน X | `+0006.17` |
| 1 | ขนาดแกน Y | `+0006.16` |
| 2 | opening ซ้าย | `+0003.10` |
| 3 | opening ขวา | `+0003.07` |
| 4 | opening บน | `+0003.02` |
| 5 | opening ล่าง | `+0003.14` |
| 6 | offset X | `+0000.04` |
| 7 | offset Y | `+0000.12` |

**ตัวอย่างคำตอบที่ใช้ได้จริง** (วัดสำเร็จ ทุกช่อง OK)

```
GM,8,+0006.17,1,0,+0006.16,1,0,+0003.10,1,0,+0003.07,1,0,+0003.02,1,0,+0003.14,1,0,+0000.04,1,0,+0000.12,1,0\r
```

**ตอนที่ยังวัดไม่เสร็จ** — ส่งค่า sentinel ให้ครบทุกช่อง Pi จะถามซ้ำเรื่อย ๆ

```
GM,8,-9999.99,4,1,-9999.99,4,1,-9999.99,4,1,-9999.99,4,1,-9999.99,4,1,-9999.99,4,1,-9999.99,4,1,-9999.99,4,1\r
```

⚠ **ห้ามส่งคำตอบสั้นกว่า 8 ชุด** — `parse_gm()` (`Pi_test.py:339`) คืน `None`
ถ้าจำนวนช่องไม่ครบ แล้ว Pi จะวนถามจนหมด `GM_MAX_WAIT` (8 วิ) แล้วถือว่าวัดไม่ติด

⚠ **ค่าติดลบทั้งหมดถูกกรองทิ้ง** — `clean_tools()` ตัด item ที่ `m < 0` ออกจาก
list **แล้ว index จะเลื่อน** · ถ้าจะจำลอง "วัดไม่ติดบางช่อง" ให้ส่งติดลบ
**ครบทั้ง 8 ช่อง** ไม่ใช่บางช่อง ไม่งั้นค่าจะถูกอ่านผิดตำแหน่ง

### ⚠⚠ ค่า "ยังวัดไม่เสร็จ" ต้องมีขนาด ≥ 9999 เท่านั้น

ห้ามใช้ `-1`, `0`, `-99` หรือค่าเล็กๆ อื่นเป็นสัญลักษณ์ "ยังไม่พร้อม" เด็ดขาด
เพราะเงื่อนไขคือ `abs(m) < 9999` = "ได้ค่าจริงแล้ว" (`NO_VALUE_ABS`)

ทดสอบจริงด้วย `-1.00` ทั้ง 8 ช่อง ได้ผลแบบนี้ — **แย่กว่าไม่ตอบเสียอีก**

```
GM,8,-0001.00,4,1, ... (8 ช่อง)
  → has_real_value เห็น |−1| < 9999 → "ได้ค่าแล้ว!" หยุดวนทันที
  → clean_tools ตัดค่าติดลบทิ้งหมด → เหลือ list ว่าง []
  → X=None · Y=None · offset=None
  → ❌ ผลตัดสิน: NG   (ถาม GM แค่ 1 ครั้ง ใช้เวลา 0 ms)
  → 🔀 → MCU: ❌ NG   ← สั่งเครื่องจริงขยับของทิ้งไปแล้ว
```

คือระบบ **ไม่รอ** และ **ไม่แจ้ง error** แต่ตัดสินเป็น NG แล้วสั่ง MCU ทันที
ใช้ `-9999.99` ตามที่ TM-X จริงใช้เท่านั้น

### 6. `S0` — กลับสู่โหมดตั้งค่า (ตอนจบ session)

```
Pi  → S0\r
ESP → S0\r
```

---

## รูปแบบตัวเลข

ของจริง TM-X ส่งมาเป็น `+0006.17` (มีเครื่องหมาย · เติมศูนย์หน้า · **2 ตำแหน่งทศนิยม**)

แต่ `parse_gm()` ใช้ `float()` แปลง — **`6.17` เฉย ๆ ก็ใช้ได้** ไม่ต้องเติมศูนย์

⚠ แต่ **ต้องเป็น 2 ตำแหน่งทศนิยม** ถ้าอยากให้ผลตรงกับหน้างาน เพราะระบบตั้ง
`_DP = 3` ไว้ตัดสิน OK/NG และหน้าเว็บแสดง 2 ตำแหน่ง

## ลำดับทั้งหมดของ 1 session (วัด 2 ชิ้น)

```
Pi → R0            ESP → R0
Pi → PW,1,201      ESP → PW

  ── ชิ้นที่ 1 ── (หลังมีคนยิง /trigger)
Pi → MRS           ESP → MRS
Pi → T1            ESP → T1
Pi → GM,3,0        ESP → GM,8,-9999.99,4,1,...     ← ยังไม่เสร็จ
Pi → GM,3,0        ESP → GM,8,-9999.99,4,1,...     ← วนทุก 20 ms
Pi → GM,3,0        ESP → GM,8,+0006.17,1,0,...     ← ได้ค่าแล้ว

  ── ชิ้นที่ 2 ── (ยิง /trigger อีกครั้ง)
Pi → MRS           ESP → MRS
Pi → T1            ESP → T1
Pi → GM,3,0        ESP → GM,8,+0006.20,1,0,...

Pi → S0            ESP → S0
```

⚠ **`S0` ยังไม่ถูกส่งจริงในโค้ดปัจจุบัน** — `finally` ปิด socket ตรง ๆ เลย
ESP ควรรับมือกับการที่ Pi ตัดสายโดยไม่บอกล่วงหน้าได้ด้วย

## ค่าเวลาที่ต้องรู้ (จาก `.env`)

| ตัวแปร | ค่า | ความหมายสำหรับ ESP |
|---|---|---|
| `SOCKET_TIMEOUT` | 5 วิ | ต้องตอบภายในเวลานี้ทุกคำสั่ง |
| `GM_MAX_WAIT` | 8 วิ | ต้องคืนค่าจริง (ไม่ติดลบ) ภายในเวลานี้หลัง `T1` |
| `GM_POLL_INTERVAL` | 0.02 วิ | ESP จะโดนถาม `GM` ~50 ครั้ง/วินาที — ต้องรับไหว |
| `T1_RETRY` / `T1_RETRY_WAIT` | 3 / 0.3 วิ | ตอบ `ER,T1,03` ได้ไม่เกิน 3 ครั้งติด |

⚠ **`GM` ถูกยิงถี่มาก (50 ครั้ง/วินาที)** — ESP ต้องตอบได้เร็วและไม่ค้าง
ถ้าใช้ `delay()` ใน loop จะทำให้ Pi timeout ทันที

## เทสต์ ESP ก่อนต่อกับ Pi

```powershell
# Windows — ต้องเปิด Telnet Client ก่อน (Turn Windows features on or off)
telnet 192.168.10.11 8600
```

หรือใช้ Python สั้น ๆ

```python
import socket
s = socket.create_connection(("192.168.10.11", 8600), timeout=5)
s.sendall(b"GM,3,0\r")
print(s.recv(1024))
```

ต้องได้สตริงที่ขึ้นต้นด้วย `GM,8,` และปิดท้ายด้วย `\r`
